# MatterTone II

A MIDI synthesizer whose sound is generated by **numerical integration of driven, dissipative
nonlinear dynamical systems**, not sample playback and not oscillator superposition. Rubber twangs,
elastic snaps, plastic pops, crackle cascades, creaks, stable nonlinear tones and subharmonics all
emerge from the state evolution of the model, which is written up in [`MODEL.md`](MODEL.md). VST3,
AU and standalone on macOS. Version 2 ("MatterTone II", beta) installs beside version 1 under its
own identity.

## The model

Each voice integrates two coupled nonlinear resonator modes with a bistable snap element, a
16-element crackle network, unilateral contact and bounded memory. A symplectic Verlet step with a
dissipative operator split keeps the energy provably non-increasing when unforced, so the sound
cannot blow up; the offline tests check that, along with determinism and the emergence of snap
events above threshold. The percussion engine adds a modal membrane with a tension potential, a
Helmholtz cavity mode and a wire contact bank for kicks and snares.

## Controls

Two pages. **instrument**: material (tension, nonlinear stiffness, hardening or softening,
damping, coupling, brittleness, adhesion, roughness, healing, memory, contact), excitation (pluck
or load-and-snap, energy, loading rate, snap depth, strike position, velocity, agitation) and the
percussion section (membrane, cavity, wires). **motion + tuning**: tuning mode, root note, mode
ratio, attractor set, scale spread, energy-to-pitch, stability bias, two LFOs with a mod matrix,
seed policy (fixed, per key, rolled each strike), output, polyphony, oversampling, body and event
mix. Every time control reads in milliseconds or beat divisions. Factory presets and named user
presets; a live CWT scalogram of the output with Morlet bandwidth, scale range, normalisation and
cone-of-influence controls. See [`KNOWN_LIMITATIONS.md`](KNOWN_LIMITATIONS.md) for caveats.

## Install a release (no build needed)

Download `MatterTone-II-2.0.1-macOS.zip` from the [Releases](https://github.com/MarioKartUltra/MatterTone/releases)
page and unzip it; that makes a folder `MatterTone-II-2.0.1-macOS`. Copy the two plug-in
bundles into the user plug-in folders, by dragging them in the Finder or with the two `cp` lines.
Then clear the quarantine flag: the bundles are signed ad hoc rather than notarised, so macOS marks
them after the download and the DAW will not load them until the mark is gone.

```sh
cd ~/Downloads/MatterTone-II-2.0.1-macOS
cp -R "MatterTone II.vst3"      ~/Library/Audio/Plug-Ins/VST3/
cp -R "MatterTone II.component" ~/Library/Audio/Plug-Ins/Components/
xattr -dr com.apple.quarantine ~/Library/Audio/Plug-Ins/VST3/"MatterTone II.vst3" \
                               ~/Library/Audio/Plug-Ins/Components/"MatterTone II.component" "MatterTone II.app"
```

Then rescan in the DAW (Ableton Live: Settings → Plug-Ins → Rescan; Logic and GarageBand pick up
the AU after a restart). `MatterTone II.app` is the standalone version with an on-screen keyboard. macOS 11 or later,
Apple Silicon or Intel.

## Build from source (macOS)

Xcode command-line tools and CMake 3.22 or later (`brew install cmake ninja`, `brew install fftw`).

```sh
git clone https://github.com/MarioKartUltra/MatterTone.git
cd MatterTone
./build.sh                 # arm64
./build.sh --universal     # arm64 + x86_64 -DFFTW_DIR=/path/to/universal-fftw
```

The first configure fetches JUCE 8.0.7 and the patched foleys_gui_magic (network, once). To build
against checkouts you already have, pass `-DJUCE_DIR=... -DFOLEYS_DIR=...` or symlink them as
`external/JUCE` and `external/foleys_gui_magic`.

FFTW3f comes from Homebrew. A universal build needs a universal static FFTW3f, passed as
`-DFFTW_DIR=<prefix>` with `lib/libfftw3f.a` and `include/fftw3.h` under it.

Artefacts land in `build/MatterTone_artefacts/Release/`. By default the VST3 and AU are also copied into `~/Library/Audio/Plug-Ins`; pass
`-DMATTERTONE_INSTALL_AFTER_BUILD=OFF` to keep them in the build directory. `-DMATTERTONE_GUI_EDITOR=ON`
opens foleys' WYSIWYG layout editor beside the plugin, for development only.

`-DMATTER_USE_FCWT=OFF` builds without the scalogram and without FFTW; `-DMATTER_USE_FOLEYS=OFF`
builds the plain editor.

```sh
ctest --test-dir build --output-on-failure    # the offline DSP checks
auval -v aumu Mtp2 Mttn                      # validate the installed AU
```

The offline harness also renders every factory preset to WAV and prints peak, RMS and measured
pitch:

```sh
./build/matter_render --out renders --sr 48000 --os 4
```
