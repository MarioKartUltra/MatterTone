# MatterTone POC

A playable MIDI synthesizer whose sound is generated by **numerical integration
of driven, dissipative nonlinear dynamical systems** — not sample playback and
not conventional oscillator superposition. Rubber twangs, elastic snaps, plastic
pops, crackle cascades, creaks, stable nonlinear tones, and subharmonics all
emerge from the state evolution of the model (see [`MODEL.md`](MODEL.md)).

Targets **VST3 + Standalone (+ AU)** on Apple Silicon / macOS, built with JUCE
and CMake. Working title: **MatterTone POC**.

---

## Requirements

* macOS on Apple Silicon, Xcode Command-Line Tools (Apple clang + macOS SDK).
* CMake ≥ 3.22 and (optionally) Ninja.
* A local **JUCE 8** checkout. The build looks for JUCE in this order:
  `-DJUCE_DIR=…` → `external/JUCE` → `~/Downloads/JUCE` → FetchContent (network).
  This repo ships a symlink `external/JUCE` → your local JUCE; adjust if needed.
* No global JUCE install is required.

Optional feature dependencies (only if you enable the flags below):

* **fCWT scalogram** (`-DMATTER_USE_FCWT=ON`): a local [fCWT](https://github.com/fastlib/fCWT)
  checkout (`-DFCWT_DIR=…` → `external/fCWT` → `~/projects/fCWT`) and **FFTW3f**
  (`brew install fftw`). Compiled scalar + single-threaded (no AVX/OpenMP needed).
* **foleys_gui_magic WYSIWYG GUI** (`-DMATTER_USE_FOLEYS=ON`): a local
  [foleys_gui_magic](https://github.com/ffAudio/foleys_gui_magic) checkout
  (`-DFOLEYS_DIR=…` → `external/foleys_gui_magic`).

## Build

The simplest path is the provided script, which **pins Apple clang + the Xcode
SDK and scrubs conda/miniforge environment variables** that would otherwise
pollute the JUCE build:

```bash
./build.sh                                        # default: dependency-free plugin
./build.sh -DMATTER_USE_FCWT=ON                   # + real-time fCWT scalogram in the editor
./build.sh -DMATTER_USE_FOLEYS=ON                 # WYSIWYG (foleys) GUI + visualisers
./build.sh -DMATTER_USE_FOLEYS=ON -DMATTER_USE_FCWT=ON   # full: WYSIWYG + scalogram widget + unified FFTW
```

Equivalent manual invocation (adjust paths as needed):

```bash
cmake -S . -B build -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_C_COMPILER=/usr/bin/clang -DCMAKE_CXX_COMPILER=/usr/bin/clang++ \
  -DCMAKE_OSX_ARCHITECTURES=arm64 \
  -DCMAKE_OSX_SYSROOT="$(xcrun --show-sdk-path)" \
  -DCMAKE_OSX_DEPLOYMENT_TARGET=11.0
cmake --build build --config Release -j
```

> **Important:** do not build with `-ffast-math` / `-ffinite-math-only` — it makes
> `std::isfinite` a no-op and defeats the NaN safety guards.

If you use JUCE as a git submodule instead of a local checkout:

```bash
git submodule update --init --recursive
```

and point `-DJUCE_DIR=external/JUCE` at it.

## Artifacts, install, and running

After a build, artifacts are under `build/MatterTone_artefacts/Release/`:

* **VST3**: `VST3/MatterTone.vst3`
* **Standalone**: `Standalone/MatterTone.app`
* **AU**: `AU/MatterTone.component`
* **Offline harness**: `build/matter_render`

`COPY_PLUGIN_AFTER_BUILD` installs the VST3/AU into your user plug-in folders
automatically:

* VST3 → `~/Library/Audio/Plug-Ins/VST3/MatterTone.vst3`
* AU   → `~/Library/Audio/Plug-Ins/Components/MatterTone.component`

To copy manually: `cp -R build/.../VST3/MatterTone.vst3 ~/Library/Audio/Plug-Ins/VST3/`.

**Ableton Live 11**: Preferences → Plug-Ins → enable VST3, then *Rescan*. The
plugin appears as an instrument under "MatterTone". **Standalone**: `open
build/MatterTone_artefacts/Release/Standalone/MatterTone.app` and choose an audio
device + MIDI input in its options.

## Tests

```bash
ctest --test-dir build --output-on-failure     # runs the DSP core test suite
# or directly:
./build/matter_render --test-only
```

The suite covers: zero-input energy decay (H non-increasing, bounded below),
no-force equilibrium, dissipation-sign, a 30 s bounded stress test at extreme
parameters, 44.1-vs-96 kHz consistency, bit-exact determinism, bistable event
emergence (and non-emergence below threshold), and silence-after-decay.

## Offline preset renders

```bash
./build/matter_render --out renders --sr 48000 --os 4
```

writes a WAV per factory preset into `renders/` and prints peak / RMS / measured
dominant frequency. This is for development verification only — it does not
replace real-time synthesis.

## Parameters (four panels)

* **Material** — Tension, Nonlinear Stiffness, Hardening/Softening, Damping,
  Nonlinear Damping, Coupling, Brittleness, Adhesion, Roughness, Healing, Memory,
  Contact Hardness, Contact Loss, Crackle Coupling.
* **Excitation** — Excitation Mode (Pluck / Load-Snap), Pluck Energy, Loading
  Rate, Snap Depth, Strike Position, Velocity Sensitivity, Agitation.
* **Dynamics / Tone** — Tuning Mode, Root Note, Mode Ratio, Attractor Set, Scale
  Spread, Energy→Pitch, Stability Bias.
* **Output / Global** — Output, Polyphony (1–8), Oversampling (2/4/8×), Seed, Body
  Mix, Event Mix. Plus **Reset Material** and **Panic** buttons.

Factory presets: Rubber Twang, Tight Elastic Snap, Plastic Pop, Dry Crackle,
Avalanche Crackle, Creaking Joint, Stable Nonlinear Bell, Subharmonic Drone,
Mode-Locked Scale, Unfamiliar Attractor Scale. Presets are parameter states —
never audio files.

See [`MODEL.md`](MODEL.md) for the equations and [`KNOWN_LIMITATIONS.md`](KNOWN_LIMITATIONS.md)
for caveats.
